# ข้อกำหนด Dashboard แผนที่แม่ปิง

## คำถามหลัก

ผู้ใช้ต้องเห็นทันทีว่า “พื้นที่ใดกำลังมีฝน/อุณหภูมิเท่าใด ข้อมูลมาจากอะไร สดแค่ไหน และเชื่อถือได้ระดับใด”

## แผนที่หลัก

ชั้นข้อมูลที่เปิด–ปิดได้:

1. แนวเขตอุทยานและ buffer 25/75 กม.
2. หน่วย HQ และ มป.1–มป.12 โดยใช้สัญลักษณ์ต่างกันสำหรับ exact/area/unknown
3. สถานีฝนและอุณหภูมิของหน่วยงานภายนอกใน buffer
4. Radar/QPE ล่าสุดพร้อมเวลาและ coverage mask
5. NASA IMERG Early/Late/Final ตามโหมดเวลาที่เหมาะสม
6. Forecast grid/ensemble ของแต่ละโมเดล
7. DEM, slope และ elevation band

## แถบสรุป

- ฝนสะสม 24/48/72 ชั่วโมงของพื้นที่อุทยาน
- อุณหภูมิ ณ 07:00 น. และต่ำสุด–สูงสุด
- จำนวนจุดที่มี ground observation ล่าสุด
- จำนวนจุดที่ข้อมูลล่าช้าหรือขาด
- ความมั่นใจของ forecast 24/48/72 ชั่วโมง แยกตาม lead time

## เมื่อกดจุดบนแผนที่

- ชื่อ รหัส พิกัด ความสูง และชนิดพิกัด
- ค่าจาก sensor หากมี
- area estimate จาก radar/satellite
- forecast หลายโมเดลและช่วง uncertainty
- freshness, quality flag และ source provenance
- ประวัติ MAE/RMSE/Bias/POD/FAR/CSI ของจุดนั้น

## กฎการแสดงผล

- `Station Measurement` ใช้เฉพาะข้อมูล point ที่ยืนยันสถานีแล้ว
- `Area Estimate` ใช้กับ area anchor หรือ grid extraction
- `Forecast` ต้องแสดง issued time และ lead time
- ค่าที่เก่าเกิน freshness SLA ต้องเปลี่ยนเป็นสีเทา ไม่ค้างสีเตือนเดิม
- จุดไม่มีข้อมูลต้องแสดง “ไม่มีข้อมูล” ไม่แทนด้วย 0
- Accuracy ยังไม่พอต้องแสดง sample size และข้อความ “กำลังสะสมข้อมูล”

## ลำดับหน้าใช้งานแบบอ่านง่าย

หน้าแรกเรียงข้อมูลตามคำถามของผู้ใช้ทั่วไปก่อนรายละเอียดเชิงเทคนิค:

1. เลือกจุดรายงาน แล้วเห็นสรุปสภาพล่าสุด อุณหภูมิ ฝน 3 ชั่วโมง ฝนสะสมตั้งแต่ 07:00 น. และฝนย้อนหลัง 24 ชั่วโมงทันที
2. แสดงโอกาสฝน 6 ชั่วโมงและความชื้นช่วงใกล้ปัจจุบัน โดยระบุว่าเป็นค่าคาดการณ์จากแบบจำลอง
3. แสดงพยากรณ์รายวันสูงสุด 7 วันแบบการ์ดสั้นก่อนแผนที่
4. แสดงภาพรวมทั้งอุทยาน แล้วจึงแสดงแผนที่ รายละเอียดคุณภาพข้อมูล และตารางเปรียบเทียบ 13 จุด
5. ซ่อนกราฟรายชั่วโมงและวิธีคำนวณไว้ในส่วนที่ผู้ใช้เลือกเปิดเอง

ระบบแยกตัวชี้วัดฝนสะสมเป็นสองช่วงเวลาเพื่อไม่ให้ตีความผิด:

- “ฝนสะสมวันนี้ (ตั้งแต่ 07:00 น.)” เริ่มเวลา 07:00 น. Asia/Bangkok ของรอบวันปัจจุบันและสิ้นสุดที่ข้อมูลฝนรายชั่วโมงล่าสุด ใช้เฉพาะสถานีที่มีข้อมูลอย่างน้อย 75% ของชั่วโมงที่ควรมี
- “ฝนสะสมย้อนหลัง 24 ชั่วโมง” เป็นหน้าต่างย้อนหลังแบบ rolling window และต้องแสดงเวลาเริ่ม–สิ้นสุดจริง เช่น `25 ส.ค. 14:00–26 ส.ค. 14:00 น.`

ทั้งสองตัวชี้วัดใช้ข้อมูลฝนรายชั่วโมงที่ผ่าน quality flag และ freshness gate เท่านั้น ไม่ใช้ค่าพยากรณ์ย้อนหลังแทนฝนที่ตรวจวัด

## ลำดับการพัฒนา

1. Data readiness map จาก Master และ source status — **ทำแล้ว**
2. Live observations map หลังเชื่อม gauge/API — **ทำแล้วสำหรับ Priority 1 รุ่นทดลอง**
3. Rain/temperature forecast map หลังเริ่ม snapshot model runs — **ทำแล้วด้วย Open-Meteo baseline**
4. Accuracy map หลังมีคู่ข้อมูล 60–90 วัน — **วาง pipeline/readiness table แล้ว; กำลังสะสมคู่**
5. Bias-corrected ensemble หลังผ่าน backtest หนึ่งฤดูฝน

## Implementation snapshot 23 สิงหาคม 2569

- `dashboard/index.html` เป็นไฟล์เดียวและใช้ SVG วาด polygon/marker จึงไม่พึ่ง tile server หรือ JavaScript CDN
- มี 13 จุดรายงานและ 9 สถานีสนับสนุน โดยเก็บ DNP089 แยกจาก HQ แม้ห่างกันประมาณ 43 เมตร
- แผนที่สลับสีตามฝนสะสม 24 ชั่วโมงหรืออุณหภูมิล่าสุดได้
- เพิ่ม Area Forecast แบบกริด 5 กม. 40 ช่อง สลับฝน/อุณหภูมิ เลือกเวลาได้ 152 ชั่วโมง และเปิด–ปิดชั้นข้อมูลได้
- กริดถูก clip ด้วยแนวเขตอุทยานและวาดไว้ใต้ marker เพื่อไม่บดบังค่าตรวจวัดจริง; tooltip ระบุ `Area Forecast` ชัดเจน
- เพิ่มเส้นประอ้างอิง GISTDA/MNRE ปี 2557 เพื่อให้เห็นความต่างจาก OSM โดยไม่อ้างว่าเป็นแนวเขต DNP ปัจจุบัน
- เพิ่มสถานะ TMD QPE ASCII ในส่วนคำเตือน โดยแสดง product time/อายุและหยุดรับอัตโนมัติเมื่อเกิน 6 ชั่วโมง
- KPI แยก “ระบบด้านเทคนิค” ออกจาก “หลักฐานความแม่นยำ” เพื่อไม่รวมเป็นเปอร์เซ็นต์เดียวที่ทำให้เข้าใจผิด
- เมื่อเลือกจุดจะแสดงชนิดพิกัด ความเชื่อมั่น freshness, quality flag และอนุกรมเวลา
- ตารางแสดงสถานี shortlist ทั้งที่ใช้และพักไว้ เพื่อไม่ซ่อน coverage gap
- กราฟ forecast จะแสดงเฉพาะจุดรายงานที่มี snapshot baseline; ไม่ย้ายค่าพยากรณ์ไปผูกกับสถานีตรวจวัดคนละ location
- รอบล่าสุดเพิ่ม forecast ที่พิกัดสถานี Priority 1 โดยตรง ทำให้กราฟสถานีตรวจวัดแสดง observation ต่อด้วย forecast ได้โดยไม่ spatial join ข้ามจุด
- เพิ่มตาราง Accuracy readiness 70 กลุ่ม แสดงจำนวนคู่ จำนวนวัน MAE/RMSE/Bias/CSI และสถานะ โดยเว้นคะแนนเมื่อ `pair_count = 0`
- KPI coverage รวม 7 สถานีปฏิบัติการ โดยอุณหภูมิคำนวณเฉพาะ 4 สถานีที่มี sensor จริง และ issue count รวมผล quality gate ล่าสุด
- ยังไม่เพิ่ม buffer 25/75 กม., radar, satellite, DEM และ accuracy map เพราะต้องมีข้อมูล/สิทธิ์/ช่วงประเมินเพิ่มเติม
